# Generative-model specifications (GNN)

The files here are the canonical structural description of the agent-side
generative models this suite evaluates, written in
[Generalized Notation Notation](https://github.com/ActiveInferenceInstitute/Generalized_Notation_Notation)
(GNN v1.1):

- [`sequential_evidence_agent.gnn.md`](sequential_evidence_agent.gnn.md) — the
  binary-truth fixed-horizon agent behind `active_inference.py` (single dummy
  action, identity transition, flat preferences).
- [`reference_action_loop.gnn.md`](reference_action_loop.gnn.md) — the
  two-target/two-context action-loop reference model behind
  `scenario.py::make_reference_action_scenario`.
- [`gnn-pin.json`](gnn-pin.json) — custody pin: the upstream repository, the
  exact commit, the upstream `version` string from that revision's
  `pyproject.toml`, and the date it was recorded, plus the release `tag` and the
  parser module/class the conformance check exercises as convenience fields.

Numeric values stay generated by the runtime contracts
(`active_inference.build_generative_model`,
`scenario.make_reference_action_scenario`); the specifications declare the
structure, and any `InitialParameterization` block is checked against the real
runtime model. Validate with:

```bash
./.venv/bin/python scripts/validate_gnn_specs.py
```

`src/active_inference_power/gnn_specs.py` owns the reader, the runtime binding,
and the upstream digest comparison. `tests/test_gnn_specs.py` additionally runs
the pinned upstream parser (pinned commit's `src/gnn` extracted from Git) and
requires digest equality; it skips with an explicit reason when the sibling
`Generalized_Notation_Notation` checkout is unavailable.

Re-pinning is a deliberate change: update `gnn-pin.json` to the new canonical
release (commit + upstream `version` + `date_recorded`, with `tag` when the
release is tagged) and re-run the validation script and the conformance test.
